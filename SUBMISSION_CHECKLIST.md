# OPEN//BUILD 2026 — Submission Checklist

Use this as the final gate before submitting ChoirMate AI.

## Must-do now

- [ ] Open the public repository: https://github.com/JoshCodes-hub123/choirmate-ai
- [ ] Confirm the default branch includes the actual application source code, not only documentation.
- [ ] Commit package manifests and the Python dependency file used by the app.
- [ ] Ensure there are no API keys, tokens, passwords, or private environment files in the repository.
- [ ] Confirm the project can be started using the README instructions, or clearly state what has not been verified.
- [ ] Confirm that the repository is public and the files are visible while logged out.
- [ ] Open the deployed app in a private/incognito window and test the main learner flow.
- [ ] Run a real score-image test if time permits; record whether it succeeded.
- [ ] Confirm the open-weight model is used by the actual runtime, not only named in documentation.
- [ ] Submit the repository URL and deployed application URL in the challenge submission form, if requested.
- [ ] Save a copy or screenshot of the submission confirmation.

## Challenge evidence to include

- Problem and intended users.
- What the prototype currently does.
- Architecture and the separate roles of HOMR and SmolLM2.
- Model and dependency licences.
- Setup and reproduction steps.
- Tests actually run and their results.
- Limitations and known failures.
- Acknowledgements for starter code, dependencies, and AI-assisted development.

## Do not claim without evidence

- That a real uploaded score was successfully recognised if only invalid-image tests were run.
- That SmolLM2 performed inference if only a health endpoint was checked.
- That a deployed service is available if only the local development server was tested.
- That a demo score came from the user's uploaded image.
